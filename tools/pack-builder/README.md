# oct-pack-build

Standalone, offline Node.js 24+ CLI and TypeScript library for compiling food catalogs into schema-v1 `.octpack.sqlite` packs. Uses built-in `node:sqlite` with FTS5; no backend, account, native npm addon, C++ compiler, or network call at runtime. Zod is the only runtime npm dependency (MIT). TypeScript and Node types are development dependencies (Apache-2.0 / MIT). This package's code is MIT licensed; source dataset licenses remain separate and are recorded in each pack.

From this directory:

```powershell
npm install --no-package-lock
npm run typecheck
npm test
node src/cli.ts --help
```

Node 24 strips erasable TypeScript directly. `package.json` exposes the executable name `oct-pack-build` for local installation/linking; `node src/cli.ts` and `npm run build -- ...` work without linking it. FTS5 was verified with Node 24.20.0 on Windows. Other Node distributions must include FTS5; missing support produces a SQLite error before publication.

## CLI

```powershell
# Self-contained custom JSON catalog
node src/cli.ts --format json --input tests/testdata/custom.json --output custom.octpack.sqlite

# CSV plus metadata JSON
node src/cli.ts --format csv --input tests/testdata/custom.csv --meta tests/testdata/meta.json --output csv.octpack.sqlite

# Official extracted Foundation or SR Legacy CSV directory
node src/cli.ts --format usda-fdc --input C:/datasets/FoodData_Central_csv --output usda.octpack.sqlite

# Validate any pack without changing its contents
node src/cli.ts --validate custom.octpack.sqlite
```

Output reports are JSON on stdout; warnings and errors use stderr. Exit status is 0 for success and 1 for invalid arguments, invalid data, unreadable inputs or invalid packs. `--force` permits replacing an existing output only after its replacement has built and validated. Output filenames must end in `.octpack.sqlite`; parent directories must exist. Build directly on a local filesystem that supports hard links (NTFS on Windows): publication without `--force` uses an atomic, exclusive hard link to prevent overwriting a concurrently created file. Temporary files are cleaned up on handled errors. An abruptly killed process may leave a UUID-named `.tmp` file.

## Custom JSON

A document contains exactly `pack_meta` and `foods`. Alternatively, supply a food array with `--meta meta.json`. `--meta` overrides embedded metadata when both exist. Unknown fields are rejected so misspelled nutrient names cannot silently disappear.

```json
{
  "pack_meta": {
    "pack_id": "my-catalog",
    "name": "My household foods",
    "version": "2026-11-23",
    "kind": "custom",
    "region": "IN",
    "license": "CC0-1.0",
    "attribution_text": "Catalog compiled by its author.",
    "attribution_url": "https://example.org/catalog"
  },
  "foods": [{
    "id": "lentils-cooked",
    "name": "Cooked lentils",
    "prep_state": "cooked",
    "basis": "per_100g",
    "kcal": 116,
    "protein_g": 9,
    "carbs_g": 20,
    "fat_g": 0.4,
    "fiber_g": null,
    "sodium_mg": 0,
    "aliases": [{ "alias": "dal", "lang": "hi-Latn" }],
    "units": [{ "label": "1 katori", "grams": 150 }],
    "barcodes": [{ "raw_code": "036000291452", "symbology": "UPC-A" }]
  }]
}
```

Only assign licenses you have the right to assign. The example barcode is illustrative.

| Metadata field | Rule |
| --- | --- |
| `pack_id`, `name`, `version`, `license`, `attribution_text` | Required nonempty strings |
| `kind` | `reference`, `branded`, `regional`, or `custom` |
| `region`, `attribution_url` | Optional / `null`; attribution URL must be a URL |
| `schema_version`, `built_at`, `food_count` | Generated by builder; do not include in input |

| Food field | Rule |
| --- | --- |
| `id`, `name` | Required nonempty strings; IDs unique within the pack |
| `prep_state` | Required: `raw`, `cooked`, `prepared`, or `unknown` |
| `basis` | Required: `per_100g`, `per_100ml`, or `per_serving` |
| `kcal`, `protein_g`, `carbs_g`, `fat_g` | Required finite nonnegative numbers in the declared basis |
| `fiber_g`, `sugar_g`, `sat_fat_g` | Optional finite nonnegative grams; omitted / `null` means unknown |
| `sodium_mg`, `calcium_mg`, `iron_mg`, `potassium_mg` | Optional finite nonnegative milligrams; omitted / `null` means unknown |
| `brand`, `category` | Optional nonempty string / `null` |
| `serving_g`, `serving_ml` | Optional positive conversion for the food's stated serving / `null` |
| `quality_score` | Optional finite nonnegative source score / `null`; no scoring system is invented |
| `aliases` | Optional array of `{ "alias": "nonempty text", "lang": "optional language tag" }` |
| `units` | Optional array of `{ "label": "1 cup", "grams": 150, "ml": null }`; positive `grams` or `ml` required |
| `barcodes` | Optional array of `{ "raw_code": "string", "symbology": "string" }` |

**Unknown is SQL `NULL`; an explicit zero remains zero.** JSON numeric strings and empty strings are rejected. Energy is always the provided source energy, even if it differs from `4P + 4C + 9F`. Nutrients are not rescaled; the input declares their basis. A volume never implies a weight. Supplying `serving_g` / `serving_ml` and food-specific units is optional, including for `per_serving` records.

## Custom CSV

Use the same flat food columns as JSON. Required headers are `id,name,prep_state,basis,kcal,protein_g,carbs_g,fat_g`. Supply metadata separately with `--meta`. Optional columns may be absent. Blank optional numeric cells become SQL `NULL`; the decimal literal `0` remains zero. Blank required numeric cells fail validation. Numbers use a dot decimal separator; scientific notation is accepted, thousands separators and hex numbers are rejected.

The optional `aliases`, `units`, and `barcodes` cells contain JSON arrays. Quote the entire cell and double inner quotes according to RFC 4180. See [tests/testdata/custom.csv](tests/testdata/custom.csv) for a complete example. The streaming parser accepts UTF-8 BOMs, CRLF/LF, quoted commas, escaped quotes, and quoted multiline fields; malformed quotes, duplicate headers, unknown columns, and inconsistent record widths fail the build.

## USDA FoodData Central CSV

Extract an official Foundation Foods, SR Legacy, or combined CSV archive from [USDA's dataset downloads](https://fdc.nal.usda.gov/download-datasets/). Put these files at the directory's top level:

- `food.csv`: `fdc_id`, `data_type`, `description` (optional `food_category_id`).
- `food_nutrient.csv`: `fdc_id`, `nutrient_id`, `amount`.
- `food_portion.csv`: `fdc_id`, `amount`, `measure_unit_id`, `gram_weight` (optional `portion_description`, `modifier`).
- `measure_unit.csv`: `id`, `name`.

Additional official columns are accepted. Only `foundation_food` and `sr_legacy_food` records are selected. IDs become `fdc:<fdc_id>`, basis is `per_100g`, and `category` preserves the source category ID as text (no category names are invented). Prep state is inferred from whole words in the description; `raw` / `uncooked` take precedence, then cooked preparation words, then prepared / ready-to-eat phrases, otherwise `unknown`.

| Output | FDC nutrient ID |
| --- | --- |
| kcal | 1008, fallback 2048 (specific Atwater), then 2047 (general Atwater) |
| protein / carbohydrate / total fat | 1003 / 1005 / 1004 |
| fiber / total sugars / saturated fat | 1079 / 2000 / 1258 |
| sodium / calcium / iron / potassium | 1093 / 1087 / 1089 / 1092 |

These IDs and portion semantics follow USDA's [Foundation documentation](https://fdc.nal.usda.gov/Foundation_Foods_Documentation/) and [download field descriptions](https://fdc.nal.usda.gov/docs/Download_Field_Descriptions_Oct2020.pdf). Missing optional nutrients remain `NULL`. Foods without energy or any required macro are skipped with an aggregate warning; values are never inferred as zero. Conflicting duplicate nutrient amounts fail the build. Blank nutrient amounts are unknown. Negative / non-finite selected nutrient values fail validation.

Portion weight belongs to its complete label: `amount=2`, `modifier=tablespoons`, `gram_weight=30` becomes **2 tablespoons = 30 g**. A nonempty source portion description is preferred as the label. No global mass/volume conversion is applied. Portions without positive weight or a meaningful label are skipped with an aggregate warning. A directory yielding no complete foods is rejected.

USDA metadata defaults to pack ID `usda-fdc`, region `US`, and today's ISO date for version. `--meta` can supply a full alternative metadata object, useful for choosing a release version and unique pack ID. The adapter always sets kind `reference`, license `CC0-1.0`, and USDA attribution. CSV input streams; selected food records, selected nutrient values and their portions stay in memory. This targets Foundation/SR Legacy, not the complete branded-food corpus. JSON custom catalogs are loaded in memory.

## Barcode semantics

Normalization follows the [GS1 General Specifications](https://ref.gs1.org/standards/genspecs/) and validates the modulo-10 check digit before storing a 14-digit string. Leading zeros must be retained in source strings. Symbology names are case insensitive and may use spaces, underscores, or hyphens.

- `UPC-E`: exactly 8 digits including number system 0/1 and check digit; expand to UPC-A, then pad to 14. Six-digit ambiguous forms are rejected.
- `UPC-A`, `EAN-8`, `EAN-13`, `GTIN-8/12/13/14`, `ITF-14`: validate their declared length and check digit, then zero-pad to 14.
- `GS1-128`, `GS1 DataMatrix`, `GS1 QR`: extract an initial explicit `(01)` GTIN or initial AI `01` (optionally preceded by scanner identifiers `]C1`, `]d2`, `]Q3`). Other GS1 application identifiers are not parsed. AI 01 must come first.
- Other non-GTIN symbologies retain `raw_code` and `symbology` with SQL `NULL` for `gtin14`; generic Code 128 / QR payloads are not guessed as GTINs.

The same digits `01234565` are valid UPC-E and EAN-8, but normalize to different IDs: `00012345000065` and `00000001234565`. Raw code is therefore not unique; lookup should use the supplied symbology and normalized GTIN where possible. Invalid declared GTINs fail the build.

## Pack contract and validation

The builder creates the canonical `pack_meta`, `foods`, `food_aliases`, `food_units`, `food_barcodes` tables and required foreign keys, CHECK constraints and indexes. `foods_fts` is a populated, content-bearing FTS5 table with `food_id UNINDEXED, name, brand, aliases` and tokenizer `unicode61 remove_diacritics 2`. Aliases are concatenated in insertion order. Transliterations must be supplied explicitly; Unicode diacritic folding does not invent them. FTS5 `bm25()` is meaningful within one pack only.

Finalization runs FTS `optimize`, commits, sets journal mode `DELETE`, runs `ANALYZE`, then `VACUUM`. Both `pack_meta.schema_version` and `PRAGMA user_version` are 1. Output is ready for read-only SQLite mounting; OS file permissions are not changed. Open it with `{ readOnly: true }`. It contains no runtime dependency on this compiler.

`--validate` checks SQLite integrity, exact canonical column definitions, nullable optional columns without zero defaults, required CHECK constraints / foreign keys / indexes, metadata/version/count, finite nonnegative nutrients, positive unit conversions, GTIN check digits and stored normalization, FTS content parity and queryability, and DELETE journaling. It reports table counts, file size, and known/missing/explicit-zero/percent coverage for all optional nutrients. Constraint SQL checks expect the canonical v1 expressions emitted by this builder; a semantically equivalent third-party DDL spelling may need canonicalization.

A finished database alone cannot prove that a producer preserved unknown source values: an erroneous zero is indistinguishable from a real zero. The validator checks schema nullability and reports coverage; adapter tests establish the source `NULL` versus `0` invariant. Validation opens the pack read-only and never repairs or mutates it.

## Library

```typescript
import { buildPack, jsonDataset, validatePack } from './src/index.ts';

const dataset = await jsonDataset('foods.json');
const { output, report, warnings } = await buildPack(dataset, 'foods.octpack.sqlite');
console.log(output, report.counts, warnings);
console.log(validatePack(output));
```

`buildPack` also accepts `{ meta, foods, warnings: [] }` with a synchronous or asynchronous iterable of `FoodInput`, so callers can supply their own streaming adapters. `csvDataset`, `usdaDataset`, schemas, GTIN helpers, schema SQL and version are exported. Metadata and food types are exported for TypeScript callers. `buildPack(..., { overwrite: true, builtAt: '2026-11-23T00:00:00.000Z' })` supports explicit replacement and a controlled build timestamp.

Tests use synthetic, self-contained input in `tests/testdata/`; they never download a USDA dataset or touch `fixtures/`.
